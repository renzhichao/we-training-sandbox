# 技术设计文档：银行测试规范问答（基于知识库附件）

## Requirement
基于知识库上传的 3 份银行测试规范文档（接口测试规范 v1.2 / 性能测试规范 v2.0 / 缺陷管理规范 v1.1），严格依据附件内容回答 5 个测试规范问题，每题注明出处文档与章节，未覆盖的问题标注"规范中未找到"，并输出《知识库覆盖说明》。

## Approach
本任务的核心约束是"严格基于附件文档内容回答"。**附件文档内容已在任务输入中完整提供**（接口测试规范 v1.2、性能测试规范 v2.0、缺陷管理规范 v1.1 三份文档的全文提取文本），因此实现 agent 必须**基于这些真实文档内容逐题作答**，不得臆造，也不得因工作区中无 .docx 文件而误判"规范中未找到"。

> ⚠️ 注意：仓库内既有 `docs/architecture.md` 与旧版 `docs/design-doc.md` 声称"附件文档缺失、全部标注规范中未找到"，**该前提已被任务输入中的文档全文证伪**。本设计文档取代旧版结论，作为实现契约：实现 agent 以任务输入中提供的三份文档提取文本为唯一权威来源作答。

实现策略：生成一份符合题目输出格式的 Markdown 交付文档 `docs/answer.md`，包含 5 个问题节（题号/问题/答案/出处）与《知识库覆盖说明》。每题答案直接引用对应文档原文数值，出处精确到"文档名 + 章节号"。

## Affected Files
- `docs/answer.md` — **新建**交付文档。按题目要求的格式输出 5 节回答 + 《知识库覆盖说明》。每节结构为：题号 / 问题 / 答案 / 出处。答案严格引用附件原文，出处精确到文档名与章节号（见下方"答案与出处对照表"）。
- `docs/design-doc.md` — 本设计文档（当前文件），作为实现契约；已修正旧版"附件缺失"的错误前提。
- `docs/architecture.md` — 建议同步修正其中"附件文档缺失、全部标注规范中未找到"的错误结论，改为指向本设计文档的正确出处（可选，不影响交付文档生成）。
- `tests/` — 无自动化测试要求；本任务为文档交付任务，不涉及代码逻辑，无需新增测试文件。

## Interface Changes
No interface changes.（本任务为纯文档交付，无代码、API、类型或数据库 schema 变更。）

### 出处精确性说明（实现 agent 需注意）
- 第 4 题"耗时断言红线"的 **3 秒** 出自《接口测试规范 v1.2》§5 断言规范（交易类接口耗时断言）。《性能测试规范 v2.0》§3 指标门槛另给出交易类接口 P95 ≤ 1500ms、P99 ≤ 2000ms 的分位值红线，但题目问的是"耗时断言红线"，应引用接口测试规范 §5 的 3 秒，**不得混淆**。若实现 agent 认为需补充，可在答案中注明性能规范的分位值作为补充信息，但主答案必须为 3 秒。
- 第 5 题"重开 2 次以上"出自《缺陷管理规范 v1.1》§2 缺陷生命周期分支状态中的"重开（Reopened）"条目。

### 《知识库覆盖说明》内容要求
列出 3 份文档及其适用范围（均可在文档"目的与适用范围"章节找到）：
- 《接口测试规范 v1.2》—— 适用于手机银行、网上银行、开放平台等渠道接入的交易类与查询类接口的黑盒测试（§1 目的与适用范围）。
- 《性能测试规范 v2.0》—— 适用于渠道类交易接口、账务类核心交易及批量作业的性能验证（§1 目的与适用范围）。
- 《缺陷管理规范 v1.1》—— 适用于缺陷的等级定义、生命周期、缺陷单要素、回归验证与月度缺陷分析（§1 缺陷严重等级定义 及全文）。

## Edge Cases
- 附件文档缺失 → 不适用：附件全文已在任务输入中提供，实现 agent 必须基于真实内容作答，不得臆造，也不得误标"规范中未找到"。
- 题目要求"每题注明出处文档与章节" → 出处字段必须精确到"文档名 + 章节号"（如《接口测试规范 v1.2》§3.1），不得只写文档名。
- 第 4 题存在跨文档相似指标（接口规范 3 秒 vs 性能规范 P95/P99 分位值）→ 主答案引用接口测试规范 §5 的 3 秒；如需补充性能规范分位值，须明确标注为补充信息，避免混淆。
- 输出格式要求（题号/问题/答案/出处 + 覆盖说明）→ 严格遵循题目给定的分节结构，5 题全部有明确答案，不省略任何一节。
- 若后续附件内容与任务输入不一致 → 以任务输入中提供的文档提取文本为准，并复核出处。
