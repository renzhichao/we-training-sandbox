# 银行测试规范知识库 — 架构与设计文档

> 版本：1.0 ｜ 关联交付：`docs/answer.md`（规范问答）、`docs/design-doc.md`（实现契约）
> ⚠️ 本文档描述的知识库内容（星辰银行测试规范）均为虚构培训材料，仅用于培训实操，不涉及任何真实银行数据。

---

## 1. Overview and Purpose

### 1.1 背景
星辰银行测试技术团队沉淀了 3 份核心测试规范文档，作为接口测试、性能测试与缺陷管理的统一基线。本架构文档描述围绕这 3 份规范构建的"测试规范知识库"系统的整体架构、数据模型、访问入口与非功能要求，使后续 agent 与工程师能够据此生成、校验与交付符合规范的测试用例与文档。

### 1.2 目的
- 统一 3 份规范文档的存储、版本与引用方式；
- 提供规范问答（如 `docs/answer.md` 中的 5 个问题）的权威出处索引；
- 为测试用例生成、回归策略与缺陷升级提供可追溯的依据；
- 明确各文档的适用范围，避免跨文档指标混淆（如"耗时断言红线"与"性能分位值红线"）。

### 1.3 适用范围
本知识库覆盖三类测试活动：
1. **接口测试**（黑盒）：手机银行、网上银行、开放平台等渠道的交易类与查询类接口；
2. **性能测试**：渠道类交易接口、账务类核心交易及批量作业；
3. **缺陷管理**：缺陷等级、生命周期、缺陷单要素、回归验证与月度分析。

## 2. Architecture and Key Components

### 2.1 总体架构（分层视图）

```
┌─────────────────────────────────────────────────────────────┐
│  交付层 (Delivery)                                          │
│  docs/answer.md · docs/design-doc.md · docs/architecture.md │
├─────────────────────────────────────────────────────────────┤
│  知识层 (Knowledge)                                         │
│  规范文档索引 · 章节引用表 · 出处映射 · 适用范围清单        │
├─────────────────────────────────────────────────────────────┤
│  规范层 (Specification)                                     │
│  接口测试规范 v1.2 · 性能测试规范 v2.0 · 缺陷管理规范 v1.1  │
├─────────────────────────────────────────────────────────────┤
│  数据层 (Data)                                              │
│  规范原文提取文本 · 版本元数据 · 章节号                     │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 核心组件

| 组件 | 职责 | 对应文档 |
|------|------|----------|
| **规范文档库** | 存储 3 份规范的权威原文与版本号 | 接口 v1.2 / 性能 v2.0 / 缺陷 v1.1 |
| **章节引用索引** | 将每个规范条目映射到"文档名 + 章节号" | §1~§8（各文档） |
| **出处映射表** | 记录问答答案与规范原文的对应关系 | `docs/design-doc.md` 对照表 |
| **适用范围清单** | 声明各文档的适用边界，防止跨文档误用 | 各文档 §1 目的与适用范围 |
| **问答交付器** | 按"题号/问题/答案/出处"格式生成交付文档 | `docs/answer.md` |

### 2.3 关键设计原则
- **原文权威**：所有答案严格引用规范原文，不臆造数值或章节；
- **出处可追溯**：每个答案必须精确到"文档名 + 章节号"；
- **未覆盖显式标注**：规范中未找到的内容明确标注"规范中未找到"；
- **跨文档防混淆**：相似指标（如耗时红线）须区分来源文档。

## 3. Data Models and Flows

### 3.1 数据模型

**规范文档（SpecificationDocument）**
```
{
  id: string,            // 如 "api-testing-spec-v1.2"
  title: string,         // 如 "星辰银行接口测试规范"
  version: string,       // 如 "v1.2"
  department: string,    // 发布部门，如 "测试技术团队"
  scope: string,         // 适用范围（取自 §1）
  sections: Section[]    // 章节列表
}
```

**章节（Section）**
```
{
  number: string,        // 如 "3.1"
  title: string,         // 如 "边界值取值标准（强制）"
  content: string,       // 章节原文
  mandatory: boolean     // 是否强制要求
}
```

**规范条目（SpecEntry）** — 问答与出处映射的最小单元
```
{
  questionId: number,        // 题号 1~5
  question: string,          // 问题原文
  answer: string,            // 答案（引用原文）
  sourceDoc: string,         // 出处文档，如 "《接口测试规范 v1.2》"
  sourceSection: string      // 出处章节，如 "§3.1"
}
```

### 3.2 数据流

```
规范原文提取文本
   │
   ▼
[规范层] 解析为 文档/章节/条目 结构
   │
   ▼
[知识层] 建立 出处映射 + 适用范围清单
   │
   ▼
[交付层] 按题目格式生成 docs/answer.md
   │
   ▼
[校验] 逐题核对答案与出处（对照 design-doc.md 契约）
```

### 3.3 关键出处映射（示例）

| 题号 | 出处文档 | 章节 |
|------|----------|------|
| 1 | 《接口测试规范 v1.2》 | §3.1 边界值取值标准（强制） |
| 2 | 《接口测试规范 v1.2》 | §3.1 边界值取值标准（强制） |
| 3 | 《接口测试规范 v1.2》 | §4 用例优先级定义 |
| 4 | 《接口测试规范 v1.2》 | §5 断言规范 |
| 5 | 《缺陷管理规范 v1.1》 | §2 缺陷生命周期 |

## 4. Entry Points and APIs

### 4.1 交付入口
- **`docs/answer.md`** — 面向业务方的规范问答交付物（5 节问答 + 覆盖说明）；
- **`docs/design-doc.md`** — 面向实现 agent 的实现契约（答案与出处对照表、验收标准）；
- **`docs/architecture.md`** — 本文档，面向架构与维护人员。

### 4.2 查询接口（逻辑 API）
知识库对外暴露以下逻辑查询能力：

| 接口 | 入参 | 返回 |
|------|------|------|
| `getSpec(docId)` | 文档 ID | 规范文档全文与版本 |
| `getSection(docId, sectionNo)` | 文档 ID + 章节号 | 章节原文 |
| `resolveAnswer(questionId)` | 题号 | 答案 + 出处（文档/章节） |
| `getScope(docId)` | 文档 ID | 适用范围声明 |
| `listAllDocs()` | — | 3 份规范文档清单 |

### 4.3 使用示例
```
resolveAnswer(4)
  → { answer: "3 秒", sourceDoc: "《接口测试规范 v1.2》", sourceSection: "§5" }
```

## 5. Dependencies and Technology Stack

### 5.1 技术栈
- **文档格式**：Markdown（交付物）、DOCX（规范原文源文件，经提取为文本）；
- **内容提取**：DOCX 文本提取工具（将 .docx 转为可解析的 Markdown 文本）；
- **版本控制**：Git（以 PR 形式交付，见 README）；
- **交付载体**：`docs/` 目录下的 Markdown 文档。

### 5.2 依赖关系
```
docs/answer.md        ── 依赖 ──▶ 规范原文提取文本（接口/性能/缺陷）
docs/design-doc.md    ── 依赖 ──▶ 出处映射表 + 验收标准
docs/architecture.md  ── 依赖 ──▶ 3 份规范文档结构 + 适用范围
```

### 5.3 无外部运行时依赖
本知识库为纯文档交付，无代码、API、数据库或第三方服务依赖；所有内容以 Markdown 静态文档形式维护。

## 6. Non-functional Considerations

### 6.1 安全（Security）
- 规范内容均为虚构培训材料，不涉及真实银行数据；
- 敏感字段（金额等）在规范中仅作示例，实际测试须遵循"不得在日志与响应中出现明文全量脱敏遗漏"（接口规范 §6）；
- 文档交付不包含任何密钥、凭据或令牌。

### 6.2 可扩展性（Scalability）
- 知识库以"文档 + 章节 + 条目"三层结构组织，新增规范文档只需追加文档节点并建立出处映射；
- 问答交付器按统一格式输出，新增问题无需改动整体架构；
- 适用范围清单可随文档版本演进更新。

### 6.3 可观测性 / 可追溯性（Observability）
- 每个答案均可通过"文档名 + 章节号"回溯到规范原文，保证可审计；
- 版本号（v1.2 / v2.0 / v1.1）随文档维护，防止引用过期内容；
- 跨文档相似指标（如接口规范 §5 的 3 秒耗时红线 vs 性能规范 §3 的 P95/P99 分位值）在出处映射中显式区分，避免混淆。

### 6.4 一致性（Consistency）
- 所有答案以任务输入中提供的规范原文提取文本为唯一权威来源；
- 若后续附件内容与任务输入不一致，以任务输入为准并复核出处；
- 未覆盖的问题必须显式标注"规范中未找到"，不得臆造。
